# ESP32-C3 display smoke firmware

This ESP-IDF 5.5.3 project targets the 8 MB flash, no-PSRAM FoloToy AI Passport ESP32-C3. T4.0 builds a MoonBit probe (`0xA17E`) and an SDK Canvas RGB565 diagnostic scene. It does not instantiate Forest Walk or initialize audio, input, or battery hardware.

The required MoonBit toolchain is `moon 0.1.20260904 (94521db 2026-09-04)`. `moonbit-runtime.sha256` pins its distribution's compatible runtime source and headers under `MOON_HOME`. The separate upstream `moonbitlang/moonbit-native-runtime` mirror at revision `7dfc5ca94b4066fff456b0db50fc9d25deeb9cf0` lacks `moonbit_runtime.h` required by this compiler's generated C, so it is not used. Do not substitute runtime sources without updating the compiler and hash manifest together.

The display BSP is the unmodified display subset of [FoloToy/ai-passport at `c21a015d44f2bcc02b4d859532d74cd7aefe69be`](https://github.com/FoloToy/ai-passport/commit/c21a015d44f2bcc02b4d859532d74cd7aefe69be), with its MIT license and pin definitions under `components/folotoy_display/`. ESP-IDF is pinned to [v5.5.3](https://github.com/espressif/esp-idf/tree/v5.5.3). LVGL is not linked.

Source ESP-IDF's `export.sh`, then run `./device/build.sh` from the repository root. The script fails if the SDK environment, Moon version, or runtime hashes differ. It removes stale device Moon build/capture outputs, invokes `moon build --target native --release` in `device/esp32c3/moonbit`, and requires a nonempty `generated/moonbit/sources.txt`. The device package's `options.link.native.cc` invokes `tools/moon_cc_capture.py` via `PATH`. The wrapper records the real compiler arguments and copies every generated C source; an empty `-o` placeholder is only for Moon's internal build graph. ESP-IDF never reads it. Moon may create host runtime scratch objects during its own build, but these remain in ignored `_build/` and are not linked into firmware.

`components/moonbit_device` reads the captured-source manifest and compiles the C with the ESP-IDF RISC-V compiler. `components/moonbit_runtime` compiles the matching runtime C sources directly; `main/app_main.c` calls the generated probe symbol, initializes the BSP display/backlight, and calls the generated smoke-present entry. `components/display_bridge` receives synchronous SDK `FrameView::copy_rgb565_row` output and doubles each logical pixel into a 240×16 RGB565 DMA strip (7,680 bytes). It waits for each `esp_lcd` DMA transfer before reusing the strip and logs `present_us` and the approximate maximum present FPS. The 40 MHz SPI transfer lower bound for a complete 153,600-byte physical frame is about 30.7 ms, or 32.55 FPS before software and command overhead.

With a board connected, use `./device/flash.sh -p PORT` and `./device/monitor.sh -p PORT`. Check the `MoonBit bridge probe: 0xA17E` log, red/green/blue panels, portrait orientation, exact 2× pixels, backlight, and measured present latency. Firmware compilation alone does not verify panel byte order or physical orientation.
